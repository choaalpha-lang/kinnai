# KinNai MVP1 — Design Spec

ต้นแบบอ้างอิงที่คลิกได้: `prototype/index.html` เอกสารนี้ระบุสิ่งที่ต้องคงไว้เมื่อสร้างเป็นแอปจริง

## 1. หลักการ

1. ตัดสินใจ ไม่ใช่เลื่อนดู: Solo แสดงไม่เกิน 3 ร้าน Kampai ให้โหวตจาก 3–5 ร้าน ไม่มี infinite list
2. แตะน้อย: ผู้ใช้เก่าไปถึงผลได้ในแตะเดียว (ค่าเดิมถูกเลือกไว้) ทุกคนใช้งานและตัดสินใจได้โดยไม่ต้อง login (D-017) ขอ login ด้วย 2 แตะหลังตัดสินใจสำเร็จ ผู้ร่วมกลุ่ม Kampai ไม่ถูกขอ login เลย
3. ไทยก่อน อังกฤษครบ
4. ทุกหน้าจอมีสถานะ loading, empty, error และ denied-location
5. ไม่บังคับเปิด GPS

## 2. Design tokens

ใช้ชุดสีเดิมของแอป (D-019: Founder ตัดสินไม่ใช้ชุดสีของ strategy)

| Token | ค่า | ใช้กับ |
|---|---|---|
| `coral` | #E64B35 | ปุ่มหลัก, โลโก้, ร้านที่ตรงที่สุด |
| `mango` | #FFB34D | ป้ายแจ้ง, avatar, thumbnail |
| `cream` | #FFF8F0 | พื้นหลังแอป |
| `charcoal` | #252525 | ข้อความ, chip ที่เลือก |
| `green` | #27866D | สำเร็จ, เหตุผลที่ตรง, TTY ในเป้า |
| `muted` | #71685F | ข้อความรอง |
| `line` | #ECDFD3 | เส้นขอบ |

Typeface: Prompt (400/500/600/700) · ขนาด: หัวข้อ 23, หัวการ์ด 15, เนื้อหา 14, รอง 12–13 · มุมโค้ง: การ์ด 14, ปุ่ม 13, chip 11 · ตัวเลขเวลาและราคาใช้ tabular numerals

Contrast: ข้อความขาวบน coral ได้ราว 3.9:1 (คำนวณเอง) ผ่าน WCAG 2.1 AA เฉพาะตัวอักษรใหญ่หรือตัวหนา (3:1) ไม่ผ่านสำหรับตัวอักษรปกติ (4.5:1) จึงใช้กับปุ่มตัวหนาและตัวใหญ่เท่านั้น หรือเข้มเฉดปุ่มขึ้นเล็กน้อย ต้องตรวจจริงใน Gate 2 โลโก้ยังไม่ตัดสิน (Q-019)

## 3. หน้าจอและสถานะ

| หน้าจอ | สถานะ | สิ่งที่ต้องมี |
|---|---|---|
| หน้าแรก | ปกติ | คำถาม "วันนี้กินอะไรดี?", chip งบ/แนว/ระยะ, แถบตำแหน่ง, ปุ่ม "ช่วยเลือกให้หน่อย" |
| หน้าแรก | ปฏิเสธตำแหน่ง | ข้อความว่าเลือกย่านแทนได้, chip ย่าน, ปุ่มหลักปิดจนกว่าจะเลือก |
| กำลังค้นหา | loading | Skeleton 3 ใบ, หลัง 2 วินาทีแจ้งว่าช้ากว่าปกติ |
| ผลแนะนำ | 3 ร้าน | การ์ดร้าน: thumbnail, ชื่อ, ราคา/คน, ระยะ, คะแนน, เหตุผล ≥ 2 ข้อ, ปุ่ม "กินร้านนี้" ร้านแรกเด่นกว่า |
| ผลแนะนำ | 1–2 ร้าน | เหมือนข้างบน + ข้อความจำนวนที่เจอและลิงก์ขยายเงื่อนไข |
| ผลแนะนำ | 0 ร้าน | Empty state: บอกสาเหตุ, ปุ่ม "ขยายเงื่อนไขแล้วหาใหม่", ลิงก์แก้เอง |
| ผลแนะนำ | error | บอกว่าระบบค้นหาไม่ตอบ, ตัวเลือกยังอยู่, ปุ่มลองอีกครั้ง |
| ข้อเสนอเข้าสู่ระบบ (แสดงบนหน้าผลสรุปหลังตัดสินใจสำเร็จ) | ปกติ | การ์ดใต้ผลสรุป: "บันทึกไว้จัดครั้งหน้า" ปุ่ม Apple และ Google (เรียงตาม platform) และ "ไว้ทีหลัง" ไม่บังผลและปุ่มแผนที่ ไม่มีช่องกรอก |
| ข้อเสนอเข้าสู่ระบบ | ใน in-app browser / ยกเลิก / ล้มเหลว | ข้อความและปุ่ม "เปิดใน Safari/Chrome" พร้อมคำเตือนว่าข้อมูลที่ทำไว้ไม่ตามไป · ถ้ายกเลิก อยู่หน้าเดิมและข้ามได้ |
| ยืนยันแล้ว | ปกติ | ชื่อร้าน, TTY, ปุ่มแผนที่, feedback 👍/👎 + เหตุผล, เริ่มมื้อใหม่ |
| ฉัน | ยังไม่ login | การ์ด "ยังไม่ได้เข้าสู่ระบบ" บอกว่าข้อมูลอยู่ในเบราว์เซอร์นี้เท่านั้น พร้อมปุ่มเข้าสู่ระบบ |
| ฉัน | มีข้อมูล / ว่าง | บัญชีที่เชื่อมไว้ (เชื่อมเพิ่ม, ยกเลิกได้เมื่อมีมากกว่า 1), ออกจากระบบ, ความชอบ, ประวัติ, ข้อมูลและความเป็นส่วนตัว, ยืนยันสองขั้นก่อนลบ |
| Kampai (ผู้จัด) | สร้างกลุ่ม | ชื่อนัด, งบ (เพดาน), ย่าน, เวลาปิดโหวต (ค่าเริ่มต้น 5 นาที), ปุ่ม "สร้างกลุ่ม" |
| Kampai (ผู้จัด) | แชร์และรอ | ปุ่มแชร์ลิงก์, รายชื่อผู้เข้าร่วม (ชื่อเล่น), จำนวนที่ตอบแล้ว, ปุ่ม "เริ่มโหวต" (เปิดเมื่อมีผู้ตอบรวม ≥ 2) |
| Kampai (ทุกคน) | โหวต | ตัวนับเวลา, 3–5 ร้าน, ผลรวมสด, ปุ่มโหวตเปลี่ยนได้, ผู้ที่ยังไม่โหวต |
| Kampai (ผู้จัด) | เสมอ | แบนเนอร์เตือนผู้จัดพร้อมตัวนับ 5 นาที, ร้านที่เสมอพร้อมปุ่มเลือก, ปุ่ม "เริ่มโหวตใหม่" · ทุกคนเห็นว่ากำลังรอผู้จัด |
| Kampai (ทุกคน) | ปิดโดยไม่มีผล | ข้อความว่าคะแนนเสมอและผู้จัดไม่เลือกใน 5 นาที, ผู้จัดมีปุ่ม "เริ่มโหวตใหม่" (D-023) |
| Kampai (ทุกคน) | ผลสรุป | การ์ดสรุป (ร้าน ย่าน ราคา เวลาที่ใช้), ปุ่มแผนที่, ปุ่มแชร์, ปุ่ม "จัดนัดของคุณเอง" ท้ายหน้า |
| Kampai | หมดอายุ / ยกเลิก | ข้อความบอกสถานะ, ดูผลถ้ามี, ปุ่ม "จัดนัดของคุณเอง" |
| ผู้ร่วมกลุ่ม (เข้าจากลิงก์) | เข้าร่วม | ชื่อนัดและผู้จัด, ชื่อเล่น (ไม่บังคับ), เลือกประเภทอาหาร 1–2 อย่าง, ลิงก์ privacy notice, ไม่มี tab bar ไม่มี login, banner consent ไม่บังปุ่ม |

## 4. Navigation

Tab bar 3 แท็บ: **Kampai** · กินไหน · ฉัน (Kampai เป็นแท็บแรกและแท็บเริ่มต้น ตาม D-016) หน้าที่ผู้ร่วมกลุ่มเข้าจากลิงก์ไม่มี tab bar
ใน Solo ไม่มี stack ลึกเกิน 1 ชั้น การกลับจากผลไปหน้าแรกใช้ลิงก์ "แก้เงื่อนไข" และไม่รีเซ็ตนาฬิกา (A-001)

## 5. ข้อความ

- ปุ่มบอกสิ่งที่เกิดขึ้นจริง: "กินร้านนี้", "เปิดแผนที่นำทาง", "ลบข้อมูลของฉัน"
- Error บอกสาเหตุและทางแก้ ไม่ขอโทษยาว
- ไม่ใช้คำว่า "AI แนะนำ" ใน MVP1 เพราะตรรกะเป็น rule-based
- ถ้าไม่มีข้อมูลราคา แสดง "ไม่ทราบราคา" ไม่ประมาณเอง

## 6. Accessibility

Touch target ≥ 44×44 CSS px · ขยายตัวอักษรของเบราว์เซอร์ถึง 200% โดยไม่ตัดข้อความ · chip ที่เลือกแยกได้ด้วยรูปทรงและสี · เคารพ reduce motion (ปิด shimmer) · accessibility label ครบสองภาษา

## 7. ความต่างระหว่างต้นแบบกับแอปจริง

| ต้นแบบ | แอปจริง |
|---|---|
| ร้านสมมติ 15 ร้าน ระยะคงที่ | ข้อมูลจาก Places provider |
| หน้ายืนยัน Apple/Google เป็นการ์ดจำลอง | หน้า OAuth ของ Apple/Google (redirect) และตรวจ in-app browser ก่อน ปุ่มต้องทำตาม brand guideline ของ Apple และ Google |
| ตำแหน่งจำลองด้วยปุ่ม | Geolocation API ของเบราว์เซอร์ + คำอธิบายก่อนขอ |
| เก็บใน localStorage | Supabase ใต้ RLS |
| แผนที่เปิดการค้นหาย่าน | เปิดปลายทางเป็นร้านจริง |
| Emoji เป็น thumbnail | รูปจาก provider ถ้า license อนุญาต ไม่เช่นนั้นใช้ไอคอนประเภทอาหาร |
| Kampai ใช้เพื่อนจำลองและผู้ใช้เครื่องเดียว | ผู้ร่วมกลุ่มจริงผ่านลิงก์ในเบราว์เซอร์ของตนเอง (GRP-002, GRP-003) |
| ต้นแบบขอ login หลังตัดสินใจสำเร็จ ข้ามได้ (D-017) ปรับแล้ว | ขอ login ผ่าน OAuth จริงหลังตัดสินใจ ข้ามได้ |

## 8. ข้อกำหนดสำหรับ web mobile-first (D-013)

- **Viewport หลัก:** 360–430px กว้าง บน desktop แสดงเป็นคอลัมน์กลางกว้างไม่เกิน 480px ไม่ทำ layout หลายคอลัมน์ใน MVP1
- **ความสูงหน้าจอ:** ใช้หน่วย `dvh` ไม่ใช้ `100vh` เพราะแถบ address bar ของ mobile browser ย่อ/ขยายได้ และเว้น safe-area ด้านล่างให้ bottom navigation
- **Bottom navigation:** ตรึงล่าง 3 รายการ ซ่อนบนหน้าผู้ร่วมกลุ่ม
- **PWA:** manifest, ไอคอน, theme color (Cream / Coral) เพื่อให้เพิ่มลงหน้าจอหลักได้ ไม่ต้องมีข้อความชวนติดตั้งใน MVP1
- **Location prompt:** ขอเมื่อผู้ใช้กดปุ่มเท่านั้น พร้อมคำอธิบายก่อน เพราะ browser ถามครั้งเดียวและผู้ใช้ปฏิเสธแล้วแก้ยาก ต้องมีข้อความบอกวิธีเปิดสิทธิ์ใหม่
- **In-app browser:** หน้าผู้ร่วมกลุ่มต้องใช้งานครบใน in-app browser ของ LINE โดยไม่ต้องเปลี่ยนเบราว์เซอร์ ส่วนข้อเสนอ login ตรวจ user agent แล้วแสดงปุ่ม "เปิดใน Safari/Chrome" พร้อมคำเตือนว่าข้อมูลที่ทำไว้ไม่ตามไป (R-008)
- **ปุ่ม Apple / Google:** ทำตาม brand guideline ของแต่ละราย
- **ต้นแบบ HTML ปัจจุบัน** สร้างด้วย HTML/CSS/JS ธรรมดา ใช้เป็นแบบอ้างอิงของ layout, copy และสถานะต่าง ๆ ได้ แต่ไม่ใช่โค้ดที่ควรนำไปต่อยอด

## 9. UX ของผู้ร่วมกลุ่ม Kampai (ไม่ต้อง login)

1. เปิดลิงก์ในแอปแชต (มักเป็น in-app browser) เห็นชื่อนัด ชื่อผู้จัด และตัวนับเวลา ไม่มีหน้า login
2. เลือกประเภทอาหารที่อยากกิน (แตะ 1–2 ครั้ง) งบและย่านมาจากผู้จัด
3. โหวตจาก 3–5 ร้านที่ระบบเลือก
4. เห็นผลสรุปเมื่อผู้จัดปิดโหวต พร้อมปุ่มแผนที่
5. ท้ายผล มีปุ่ม "จัดนัดของคุณเอง" เป็นจุดที่ H ของ K เกิด ต้องไม่รบกวนการดูผล

เกณฑ์ที่เสนอ: โหวตเสร็จภายใน 3 แตะหลังเปิดลิงก์ (H-009 ต้องทดสอบ)
