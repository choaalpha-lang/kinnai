# KinNai MVP1 — Design Spec

ต้นแบบอ้างอิงที่คลิกได้: `prototype/index.html` เอกสารนี้ระบุสิ่งที่ต้องคงไว้เมื่อสร้างเป็นแอปจริง

## 1. หลักการ

1. ตัดสินใจ ไม่ใช่เลื่อนดู: แสดงไม่เกิน 3 ร้าน ไม่มี infinite list
2. แตะน้อย: ผู้ใช้เก่าไปถึงผลได้ในแตะเดียว (ค่าเดิมถูกเลือกไว้) ผู้ใช้ใหม่เห็นร้านก่อน แล้ว login ใน 2 แตะตอนยืนยันร้านแรก
3. ไทยก่อน อังกฤษครบ
4. ทุกหน้าจอมีสถานะ loading, empty, error และ denied-location
5. ไม่บังคับเปิด GPS

## 2. Design tokens

| Token | ค่า | ใช้กับ |
|---|---|---|
| `coral` | #E64B35 | ปุ่มหลัก, โลโก้, ร้านที่ตรงที่สุด |
| `mango` | #FFB34D | ป้ายแจ้ง, avatar, thumbnail |
| `cream` | #FFF8F0 | พื้นหลังแอป |
| `charcoal` | #252525 | ข้อความ, chip ที่เลือก |
| `green` | #27866D | สำเร็จ, เหตุผลที่ตรง, TTY ในเป้า |
| `muted` | #71685F | ข้อความรอง |
| `line` | #ECDFD3 | เส้นขอบ |

Typeface: Prompt (400/500/600/700) · ขนาด: หัวข้อ 23, หัวการ์ด 15, เนื้อหา 14, รอง 12–13 · มุมโค้ง: การ์ด 14, ปุ่ม 13, chip 11 · ตัวเลขเวลาและราคาใช้ tabular numerals

Contrast: ข้อความขาวบน coral ใช้กับปุ่มตัวหนา ≥ 15pt เท่านั้น ต้องตรวจตาม WCAG 2.1 AA ใน Gate 2 และปรับเฉดถ้าไม่ผ่าน

## 3. หน้าจอและสถานะ

| หน้าจอ | สถานะ | สิ่งที่ต้องมี |
|---|---|---|
| หน้าแรก | ปกติ | คำถาม "วันนี้กินอะไรดี?", chip งบ/แนว/ระยะ, แถบตำแหน่ง, ปุ่ม "ช่วยเลือกให้หน่อย" |
| หน้าแรก | ปฏิเสธตำแหน่ง | ข้อความว่าเลือกย่านแทนได้, chip ย่าน, ปุ่มหลักปิดจนกว่าจะเลือก |
| กำลังค้นหา | loading | Skeleton 3 ใบ, หลัง 2 วินาทีแจ้งว่าช้ากว่าปกติ |
| ผลแนะนำ | 3 ร้าน | การ์ดร้าน: thumbnail, ชื่อ, ราคา/คน, ระยะ, คะแนน, เหตุผล ≥ 2 ข้อ, ปุ่ม "กินร้านนี้" ร้านแรกเด่นกว่า |
| ผลแนะนำ | 1–2 ร้าน | เหมือนข้างบน + ข้อความจำนวนที่เจอและลิงก์ขยายเงื่อนไข |
| ผลแนะนำ | 0 ร้าน | Empty state: บอกสาเหตุ, ปุ่ม "ขยายเงื่อนไขแล้วหาใหม่", ลิงก์แก้เอง |
| ผลแนะนำ | error | บอกว่าระบบค้นหาไม่ตอบ, ตัวเลือกยังอยู่, ปุ่มลองอีกครั้ง |
| เข้าสู่ระบบ (แสดงเมื่อกด "กินร้านนี้" ครั้งแรก) | ปกติ | หัวข้อระบุชื่อร้านที่กำลังจะยืนยัน, ปุ่ม Apple และ Google (เรียงตาม platform), ข้อความรับทราบ privacy notice, ลิงก์ "กลับไปดูร้าน" ไม่มีช่องกรอก ไม่มี tab bar |
| เข้าสู่ระบบ | ยกเลิก / ล้มเหลว | อยู่หน้าเดิม บอกสาเหตุ เสนอช่องทางอื่น |
| ยืนยันแล้ว | ปกติ | ชื่อร้าน, TTY, ปุ่มแผนที่, feedback 👍/👎 + เหตุผล, เริ่มมื้อใหม่ |
| ฉัน | ยังไม่ login | การ์ด "ยังไม่ได้เข้าสู่ระบบ" พร้อมปุ่มเข้าสู่ระบบ |
| ฉัน | มีข้อมูล / ว่าง | บัญชีที่เชื่อมไว้ (เชื่อมเพิ่ม, ยกเลิกได้เมื่อมีมากกว่า 1), ออกจากระบบ, ความชอบ, ประวัติ, ข้อมูลและความเป็นส่วนตัว, ยืนยันสองขั้นก่อนลบ |
| Kampai | 5 ขั้น | แถบขั้นตอน, ป้าย "ข้อมูลจำลอง" ทุกหน้า, กรณีเสมอให้ organizer เลือก |

## 4. Navigation

Tab bar 3 แท็บ: กินไหน · Kampai · ฉัน
ใน Solo ไม่มี stack ลึกเกิน 1 ชั้น การกลับจากผลไปหน้าแรกใช้ลิงก์ "แก้เงื่อนไข" และไม่รีเซ็ตนาฬิกา (A-001)

## 5. ข้อความ

- ปุ่มบอกสิ่งที่เกิดขึ้นจริง: "กินร้านนี้", "เปิดแผนที่นำทาง", "ลบข้อมูลของฉัน"
- Error บอกสาเหตุและทางแก้ ไม่ขอโทษยาว
- ไม่ใช้คำว่า "AI แนะนำ" ใน MVP1 เพราะตรรกะเป็น rule-based
- ถ้าไม่มีข้อมูลราคา แสดง "ไม่ทราบราคา" ไม่ประมาณเอง

## 6. Accessibility

Touch target ≥ 44×44pt · รองรับ Dynamic Type ถึง 130% โดยไม่ตัดข้อความ · chip ที่เลือกแยกได้ด้วยรูปทรงและสี · เคารพ reduce motion (ปิด shimmer) · accessibility label ครบสองภาษา

## 7. ความต่างระหว่างต้นแบบกับแอปจริง

| ต้นแบบ | แอปจริง |
|---|---|
| ร้านสมมติ 15 ร้าน ระยะคงที่ | ข้อมูลจาก Places provider |
| หน้ายืนยัน Apple/Google เป็นการ์ดจำลอง | Native sign-in sheet ของระบบปฏิบัติการ ปุ่มต้องทำตาม brand guideline ของ Apple และ Google |
| ตำแหน่งจำลองด้วยปุ่ม | สิทธิ์ตำแหน่งของระบบปฏิบัติการ + หน้าอธิบายก่อนขอ |
| เก็บใน localStorage | Supabase ใต้ RLS |
| แผนที่เปิดการค้นหาย่าน | เปิดปลายทางเป็นร้านจริง |
| Emoji เป็น thumbnail | รูปจาก provider ถ้า license อนุญาต ไม่เช่นนั้นใช้ไอคอนประเภทอาหาร |
