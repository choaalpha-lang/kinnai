# KinNai MVP1 — Product Requirements Document

เวอร์ชัน: Gate 1 draft · 2026-11-11 · แก้ไข 2026-11-26 ตาม 10X Strategy v1.0 (D-016 ถึง D-022) · เจ้าของ: Founder (Yimio)
เอกสารประกอบ: `REQUIREMENTS.md` (AC รายข้อ), `DESIGN_SPEC.md`, `ANALYTICS_PLAN.md`, `DECISION_LOG.md`

## 1. ปัญหาและเป้าหมาย

คนทำงานและนักศึกษาเสียเวลาตัดสินใจว่าจะกินอะไร MVP1 ทดสอบสมมติฐานหลัก 2 ข้อ ตามลำดับความสำคัญ (D-016):

1. **Growth loop (หลัก):** Kampai Link แพร่กระจายได้ (K ≥ 1.2, H-007) กลุ่มได้ร้านภายใน 5 นาที (H-002) และผู้จัดกลับมาจัดซ้ำ (H-008)
2. **Solo (รอง):** เมื่อบอกงบ แนวอาหาร และระยะแล้ว ผู้ใช้เลือกร้านจาก 3 ตัวเลือกได้ภายใน 30 วินาที (H-001) และพอใจกับร้านนั้น (H-004)

MVP1 ถือว่าสำเร็จเมื่อผ่าน gate 90 วันของ strategy (D-020) ด้วยหลักฐานจาก beta จริง ไม่ใช่เมื่อฟีเจอร์ครบ เป้า MAU 10 ล้านและกำไร ฿1,000 ล้านเป็นเป้าทิศทาง ไม่ใช่เงื่อนไขของ spec (D-021)

## 2. ผู้ใช้เป้าหมาย

**หลัก:** กลุ่มที่ต้องเลือกร้านด้วยกันในกรุงเทพฯ ได้แก่ผู้จัด (organizer) และผู้ร่วมกลุ่ม (participant) เช่น ทีมที่ทำงาน นักศึกษา ครอบครัว ผู้ร่วมกลุ่มต้องไม่ต้องลงแอปและไม่ต้องสมัคร
**รอง:** Solo diner (พนักงานออฟฟิศ นักศึกษา) ที่ตัดสินใจมื้อกลางวันหรือมื้อเย็นใกล้ที่ทำงานหรือที่เรียน
พื้นที่เปิดตัวยังเปิดอยู่ (Q-005) เริ่มทดสอบจาก 2–3 เครือข่ายที่ไม่ทับซ้อนกัน (D-022)

## 3. ขอบเขต

**In scope (เรียงตามความสำคัญ D-016):** GRP-002 ถึง 005 (Kampai บนเว็บ), ANL-001/002, PLAT-001 ถึง 003, PRIV-001, SOLO-002/004 (ระบบแนะนำและแผนที่ที่ใช้ร่วม), SOLO-001/003/005 (Solo), AUTH-001, INT-001 (โครงข้อมูล), BRAND-001 · GRP-001 ส่งมอบแล้วเป็นต้นแบบ · WPL-001 หลัง gate วัน 60 (Could)

**Out of scope ใน MVP1 (D-008, D-013):** แอปบน App Store และ Google Play · push notification · ใช้งานออฟไลน์เต็มรูปแบบ · การชำระเงินและ subscription (Plus และ Kampai Premium ถอดแล้ว D-018) · ระบบ referral แบบให้รางวัล · ระบบ Intent Exchange และการแสดง offer (ทำเฉพาะโครงข้อมูล INT-001) · affiliate และ sponsored result · merchant portal · การแนะนำด้วย LLM · LINE Login, OTP, อีเมลและรหัสผ่าน (D-011, D-014) · รีวิวหรือรูปที่ผู้ใช้สร้าง

## 4. User flow หลัก

**Kampai (หลัก D-016)**

1. ผู้จัดเปิดแอป เข้าแท็บ Kampai ตั้งชื่อนัด งบ ย่าน แล้วสร้างกลุ่ม (ไม่ต้อง login)
2. ผู้จัดแชร์ลิงก์เข้ากลุ่มแชต
3. ผู้ร่วมกลุ่มเปิดลิงก์ เลือกประเภทอาหาร (ไม่ต้อง login) นาฬิกา Group TTY เริ่มเมื่อผู้จัดกด "เริ่มโหวต" (ตาม ANALYTICS_PLAN §3)
4. ทุกคนโหวตจาก 3–5 ร้าน
5. ปิดโหวต (ผู้ที่ไม่โหวตงดออกเสียง เสมอให้ผู้จัดเลือก โดยเตือนผู้จัดและถ้าไม่เลือกใน 5 นาทีกลุ่มปิดโดยไม่มีผลและเริ่มโหวตใหม่ได้ D-023) ได้ร้านเดียว
6. แชร์การ์ดสรุปกลับเข้ากลุ่ม และผู้ร่วมกลุ่มเห็นปุ่ม "จัดนัดของคุณเอง"
7. ผู้จัดเห็นข้อเสนอบันทึกด้วย Apple/Google (ข้ามได้ D-017)

**Solo (รอง)**

1. เปิดแอป เห็นหน้าแรกพร้อมค่าที่เลือกไว้ครั้งก่อน
2. ปรับงบ แนว ระยะ (ถ้าต้องการ) แล้วกด "ช่วยเลือกให้หน่อย" → นาฬิกา TTY เริ่ม (D-001)
3. เห็นไม่เกิน 3 ร้านพร้อมเหตุผล กด "กินร้านนี้" หรือขอชุดใหม่
4. หน้ายืนยัน: เปิดแผนที่, ให้ feedback และเห็นข้อเสนอบันทึกด้วย Apple/Google (ข้ามได้ D-017)

ทางแยก: ปฏิเสธตำแหน่ง → เลือกย่าน · ผลน้อยกว่า 3 → ขยายเงื่อนไข · error → ลองใหม่ · ลิงก์กลุ่มหมดอายุ → ดูผลหรือจัดนัดใหม่

## 5. ตรรกะการแนะนำ (rule-based)

- **กรอง:** ราคา ≤ เพดานงบ (D-002) · ประเภทตรงหรือ "อะไรก็ได้" · ระยะ ≤ ที่เลือก · ไม่อยู่ในรายการที่ผู้ใช้ 👎 · เปิดอยู่ (ถ้ามีข้อมูล)
- **จัดอันดับ:** คะแนนรีวิว − ค่าปรับตามระยะ + โบนัสเมื่อราคาอยู่ในช่วงของระดับงบ + โบนัสร้านที่เคย 👍
- **เหตุผลที่แสดง:** สร้างจากกฎเดียวกับที่ใช้จัดอันดับ ไม่ใช้ LLM
- น้ำหนักเริ่มต้นใช้ค่าจากต้นแบบ และปรับจากข้อมูล beta
- **Kampai:** กรองด้วยเพดานงบของผู้จัด และย่านที่ผู้จัดเลือก จัดอันดับตามจำนวนสมาชิกที่ประเภทอาหารตรงกับความชอบ แล้วตามคะแนนและระยะ แสดง 3–5 ร้านให้โหวต เรียกค้นหาหนึ่งครั้งต่อกลุ่ม (R-014)
- **การแยก Sponsored:** ห้ามนำข้อเสนอที่ได้รับค่าตอบแทนมาปนในผลจัดอันดับหรือผลโหวต ต้องติดป้ายและแยกชัดเจนเมื่อมีในอนาคต

ข้อจำกัดที่รู้แล้ว: ความแม่นของตัวกรองงบขึ้นกับว่า provider มีราคาต่อหัวหรือไม่ (R-001)

## 6. สถาปัตยกรรม (ระดับ Gate 1)

Managed modular monolith ตาม D-006

- **Web app (D-013):** Next.js (React) + TypeScript บน Vercel · mobile-first responsive · เพิ่มลงหน้าจอหลักแบบ PWA ได้ (manifest) · โมดูล `decision`, `preferences`, `feedback`, `analytics` · เสนอไว้ให้ยืนยันใน Gate 2 (ทางเลือก: Vite SPA ง่ายกว่า แต่ไม่มี server rendering)
- **ทางไป native ภายหลัง:** Supabase และ logic ที่เป็น TypeScript นำกลับมาใช้ได้ ส่วน UI ต้องสร้างใหม่ (เช่น Expo) หรือห่อด้วย Capacitor ตัดสินหลังมีผลทดสอบ web ยังไม่ประเมิน
- **Backend:** Supabase Postgres + anonymous sign-in + Auth (Sign in with Apple, Google) + RLS · Edge Function `search-places` (ห่อ provider, rate limit, cost cap), `confirm-decision` (idempotent), `create-group`, `cast-vote`, `close-group` · ผลโหวตแบบ realtime ด้วย Supabase Realtime หรือ polling (เลือกใน Gate 2 NFR-10)
- **ภายนอก:** Places provider (Q-001) · ลิงก์ Google Maps (เปิดแอปแผนที่ถ้ามี) · PostHog · Sentry (browser SDK)
- ไม่มี AI call ใน MVP1

รายละเอียด schema, dependency และต้นทุนเป็นงานของ Gate 2

## 7. Privacy และ PDPA (D-005)

อ้างอิง พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 ส่วนนี้เป็นการออกแบบเบื้องต้น ไม่ใช่ความเห็นทางกฎหมาย ต้องผ่าน SPIKE-002

| หัวข้อ | แนวทางใน MVP1 | มาตรา |
|---|---|---|
| ข้อมูลที่เก็บ | anonymous user ID, ความชอบ, ประวัติการตัดสินใจ, feedback, ข้อมูลกลุ่ม (ชื่อนัด, ย่าน, งบ, ชื่อเล่นไม่บังคับ, โหวต) ไม่เก็บพิกัดดิบ · เมื่อ login: Account ID จาก Apple/Google และชื่อที่แสดง การขออีเมลยังเปิดอยู่ (Q-009) | ม.22 (เก็บเท่าที่จำเป็น) |
| ผู้ร่วมกลุ่มที่ไม่มีบัญชี | ใช้ anonymous session ที่ผูกกับกลุ่ม ลบการเข้าร่วมของตนได้ ข้อมูลกลุ่มและชื่อเล่นเก็บ 30 วันหลังปิดแล้วลบ (A-011) | ม.22, ม.33 |
| Intent data (INT-001) | เก็บเฉพาะข้อมูลรวมไม่ระบุตัวบุคคล ไม่ส่งออก ไม่ขายข้อมูลส่วนบุคคล ต้องผ่าน SPIKE-002 ก่อน pilot กับแบรนด์ (R-012) | ม.19, ม.22 |
| ตำแหน่ง | ใช้เฉพาะขณะค้นหา ส่งไป Edge Function แล้วไม่บันทึก มีทางเลือก "เลือกย่านเอง" | ม.19, ม.22 |
| ฐานทางกฎหมาย | ข้อเสนอ: consent สำหรับตำแหน่งและ analytics, สัญญาสำหรับการให้บริการหลัก ต้องยืนยันใน SPIKE-002 | ม.19, ม.24 |
| การแจ้ง | Privacy notice ภาษาไทยก่อนเก็บข้อมูล | ม.23 |
| Retention | ต้องประกาศตัวเลข ข้อเสนอใน A-005 ยังรอตัดสิน (Q-002) | ม.23, ม.37(3) |
| สิทธิเจ้าของข้อมูล | ลบข้อมูลในแอป, ถอน consent ได้, ช่องทางติดต่อ controller | ม.19, ม.30–36 |
| โอนไปต่างประเทศ | Supabase, PostHog, Sentry, Places provider, Apple และ Google (ผู้ให้บริการ login) อยู่นอกไทย ต้องระบุฐานการโอน (Q-004) | ม.28–29 |
| เหตุละเมิด | Runbook แจ้ง สคส. ภายใน 72 ชั่วโมง | ม.37(4) |

| DPO / ROPA | ตรวจว่าเข้าเกณฑ์หรือได้ข้อยกเว้นหรือไม่ | ม.39, ม.41 |

## 8. Release criteria ของ MVP1

- Must ทุกข้อผ่าน Definition of Done
- Kampai ใช้งานจริงครบ flow โดยผู้ร่วมกลุ่มไม่ต้อง login และวัด K, organizer repeat, completion ภายใน 5 นาที ได้ตาม ANL-002
- ทดสอบบน iOS Safari และ Chrome Android จริง รวม in-app browser ของ LINE (R-008)
- Privacy notice และ consent ผ่านการทบทวนทางกฎหมาย
- Cost cap และ kill switch ทดสอบแล้ว
- Dashboard ตาม ANALYTICS_PLAN ใช้งานได้ก่อนเปิด beta
- Founder อนุมัติ Gate 3 และ Gate 4
